# Rules digest

Every rule of [PLAYBOOK.md](PLAYBOOK.md) in one line, without the reasons. This is the file
a coordinator agent loads; it opens the playbook section when it needs the why, the numbers
or the check. Generated by `tools/make_rules_digest.py`: do not edit by hand.

## 2. Roles, model routing and reasoning effort

- **R-route-1. Only two models: strongest for judgment and code, cheapest for bounded reading.**
- **R-route-2. Keep cheap-model readers below their price-tier boundary (e.g. < 100k prompt).**
- **R-route-3. Readers report, the strong agent judges. Every report starts with a "Flags" line.**
- **R-route-4. Delegate only when one helper replaces many calls or keeps big output out.**
- **R-route-5. Override the built-in Explore agent with a cheap-model project agent.**
- **R-route-6. Agent definition files load only at session start.**
- **R-route-7. Keep agent definitions small; they are paid on every call.**
- **R-route-8. TRIAL, not yet measured: a reader builds a source index before a consultant starts.**

## 3. Context economics

- **R-ctx-1. Never wake or resume a big-context agent without need.**
- **R-ctx-2. Fresh agent per task.** Resume an agent only for its own jobs, its own results, questions about its own work, or the next step of its own deliverable. Agents past their wrap-up point (R-ctx-3) get no new tasks.
- **R-ctx-3. One context limit per lane: 150k by default, set by workload, adjustable by the coordinator.** Size work in phases that end in a deliverable.
- **R-ctx-4. Hand off only if real work remains (~50+ calls); finish short tails in place.**
- **R-ctx-5. Lean starts for successors.** A successor reads only the HANDOFF section and the passages its next step needs. Target <= 80k context at its first report.
- **R-ctx-6. Log to a file, look at a view.** Long, costly or noisy commands write full output to a file; the agent reads `tail`, `grep -c`, `grep -m` or a summary line. If the view was too narrow, read more from the file; never rerun to see more. No single tool output above ~20 kB.
- **R-ctx-7. Probe-heavy and triage work: one call per probe series, a compact table per call.**
- **R-ctx-8. Token-saver habits in every agent.** Search before reading, read line ranges, tail and grep logs, never dump whole files or JSON, no re-reads after edits, one bounded repair.
- **R-ctx-9. Split "implement" and "verify" by design.**
- **R-ctx-10. Batch independent reads and checks into one tool call.** Cost = calls x context, not bytes read. Independent status checks, greps and file heads go into ONE shell call with separators; dependent steps stay sequential.
- **R-ctx-11. Fan-outs use a lean agent file.** For five or more agents sharing one brief, define a project agent file with `omitClaudeMd: true`, a `tools:` allowlist (which also drops MCP tool schemas), `skills:` to preload what the agent needs, and the brief as the file body. The launch prompt then carries only the work-package id.
- **R-ctx-12. Turn off unrelated MCP servers and plugins per project.** Tool schemas and server instructions of every connected server are paid in every context.
- **R-ctx-13. Image reads have a budget.** A lane that looks at its own renders or screenshots downscales them (<= 1400 px) and tiles several views into one image. The brief says: "no image reads unless one decides something you cannot measure; then one downscaled crop".
- **R-ctx-14. Cap concurrent bulk runs and estimate their tokens first.**
- **R-wait-1. Waits up to ~45 min: poll in the foreground, at most 240 s per call (never above 270 s). Longer waits: the coordinator starts a background waiter and ends its turn; a lane writes its handoff and ends, and a fresh successor collects the result.**
- **R-wait-2. Wait on job ids, never on hand-typed log markers.**
- **R-wait-3. Never run a long job as one foreground call.**
- **R-wait-4. The coordinator never blocks.** Anything over ~1 min runs in the background; the coordinator keeps answering.
- **R-wait-5. Never spawn a sub-agent to wait on, or to classify the results of, jobs that have not finished.**
- **R-wait-6. Background work only through the harness.** Use the harness's run-in-background mechanism; never start `nohup... &` inside a foreground shell call. Foreground calls stay under 2 minutes.
- **R-wait-7. Start a verification rerun in parallel with the original run**, not after it.

## 4. Briefs

- **R-brief-1. Structure every brief the same way** (template in STARTER-KIT): head, rules file, named passages to read, worktree, binding decisions, facts with evidence, steps with done-conditions, context limit and call budget, report format.
- **R-brief-2. Give file:line entry points and exact commands.**
- **R-brief-3. One rules block, pasted or referenced by path; new rules go there first.**
- **R-brief-4. Check that brief facts exist before sending.** Commits, branches, finding ids, "X is missing" claims.
- **R-brief-5. Put the slowest external dependency first.**
- **R-brief-6. Explicit caps instead of vague words.** "Short probes on the laptop" became 7,900 runs. Give numbers: run caps, slot caps, memory caps, deadlines ("until job X ends", not a fixed clock window that idles everyone else).
- **R-brief-7. Set the accept rule before the probe runs.**
- **R-brief-8. Studies end with a closer.** When a study's report lists unverified items, launch one lean read-only closer at once.
- **R-brief-9. A numeric call budget in every brief.**
- **R-brief-10. One side or layer per lane; a lane that ports your own code to another platform only coordinates.** Each file port goes to ONE sub-agent with a short brief (source file and range, target file, APIs, "write only this file, build, 5-line summary"); the lane reads only summaries and build or test tails.
- **R-brief-11. Brief checklist.** Before sending: filter the items by their current status, search for an existing fix, state every input's format, state key derivations exactly, and use a new brief name.
- **R-brief-12. Never ask a sub-agent for a full read of the coordinator's decision log.** Give it the rules digest and let it grep for specifics.
- **R-brief-13. Choose the launch form by worktree situation.** A fresh code lane gets an isolated worktree and commits at once; an in-lane successor and a lane in a second repository run without isolation.

## 5. Handoffs

- **R-ho-1. Handoff procedure (agent side).** At the trigger, FIRST write the HANDOFF section, then continue nothing else:
- **R-ho-2. Successor side.** Same worktree, same branch. First actions: read the rules file, read the HANDOFF section only, adopt every live job (`queue adopt <id> --by <me>`), follow them with the normal wait rule, resubmit only on "cancelled" or "infra failure" exits.
- **R-ho-3. After a handoff the successor owns all data, jobs and cleanup.** The predecessor never deletes anything.
- **R-ho-4. Stop the predecessor only after its jobs are adopted and detached.** Never kill another agent's job client shell.
- **R-ho-5. Never message a finished agent**, not even to acknowledge. Acknowledgements go to the coordinator (~$1-2 per wake at 250k).
- **R-ho-6. Every handoff gets a successor at once** unless the work is blocked or finished.
- **R-ho-7. Notes survive the worktree.** Agents in auto-cleaned (isolated) worktrees commit their notes and helper scripts on their branch before ending.
- **R-ho-8. Idle-between-tasks agents (stewards, waiters) use a durable worktree**, not an auto-cleaned one.
- **R-ho-9. Close the predecessor in the message that launches the successor:** "LANE CLOSED: no commits, submits or cancels; on a job end only report the id and result to the coordinator". Successor briefs name every job the predecessor still owns.
- **R-ho-10. Successor briefs are no-orientation.** Point at the HANDOFF block, name the exact file:line spots, forbid reading beyond them, ask for the first code edit by call 5, decide open questions before spawning, and give the test commands verbatim. Keep the brief under ~60 lines with the binding rules inlined.
- **R-ho-11. Check that an inherited job is alive before waiting on it** (process list plus a log modified in the last few minutes). If it is dead, requeue it under a fresh log name.
- **R-ho-12. While a lane has queued jobs, its handoff note goes to an untracked file.**
- **R-ho-13. A long-wait evidence lane is two phases.** Phase A submits and records job ids. Phase B is a fresh lean successor that only waits and judges.

## 6. Coordinator loop

- **R-loop-1. Stale sweep cleans, not only checks.** Hung, idle and spinning agents; obsolete timers and watchers; queue jobs of finished owners; idle held slots; dashboard drift; finished worktrees.
- **R-loop-2. Duties live in a registry with an evidence source each, checked by a script.**
- **R-loop-3. Reflection each sweep: projected vs target, bottleneck, stop list, one improvement.**
- **R-loop-4. Bottleneck scan each sweep, and name the binding limit.** Slots held vs cores used, declared vs written disk, RAM-scratch accounting, queue priority inversion.
- **R-loop-5. Agent scan each sweep.** Flags: SILENT (no transcript write > 15 min), NOMSG (> 60 min without a report), POLLING (> 70 % of calls are polls), CTX (> 90 % of soft), HUNG (tool call without result > 20 min).
- **R-loop-6. Self-compaction of the coordinator.** Compact at natural points (after a merge push, after a lane report is fully processed) from ~180k context (it had been 230-300k; the coordinator was 15-20 % of spend at avg 156k/call). Never compact with an unprocessed agent notification or in the middle of a discussion with the user. The coordinator does not hand off to a successor coordinator; it continues through compactions.
- **R-loop-7. Never type a clock time by hand.** Every time comes from `date` in the same command that writes it.
- **R-loop-8. Record every cleanup in the resume sheet in the same step.**
- **R-loop-9. Lost-decision audit after long multi-compaction sessions.** Extract the deduplicated user messages with a script, read them once, diff against memory and the hints file (~480 messages / 70k chars found several unrecorded decisions).
- **R-loop-10. Re-aim agents the moment a lever lands in shared code.** Message every agent working on the same code, naming the owner and the commit.
- **R-loop-11. Admission control before a wave.** Sum the slot caps of live agents; keep it <= ~1.5x the pool.
- **R-loop-12. Bookkeeping rides along.** Log lines, hints appends, digest edits and plan updates go into the same message as real work, never a call of their own. The periodic sweep prints one count line plus the non-OK lines; the full output stays in its log.
- **R-loop-13. An advisor model signs off strategy, not operations.** If a stronger consultant model reviews the coordinator, it signs off strategic items only (new decisions, rules, strategy, results), in batched check-ins triggered by content: due once a result or decision has waited ~30 min unsigned. Operations stay with the coordinator.
- **R-loop-14. A scheduled follow-up must be proven runnable.** After creating a scheduled task, run a throwaway probe once and check which model and configuration it started with.
- **R-loop-15. A job that must be started again carries its own command.** A recurring background job (sweep timer, watcher) is started by a script kept in the repository. The script prints the command that starts it again as its last output line. The carry block lists the background shells by purpose and, for each job that has to be started again, the exact command.
- **R-loop-16. Orientation after a compaction is one script.** After a compaction the coordinator reads the rules digest once and runs one script. The script prints the hints lines newer than the digest header, the head of the state file, the live lanes, the tail of the duties log, and the size of each capped file against its cap.
- **R-loop-17. An agent whose deliverable is a report writes the report file first.** A consultant, advisor or reviewer creates its report file with an outline right after orientation and fills it as it goes. A stop at any point then leaves a usable report. Its agent type gets `"deliverable": "report"` in the context guard's `agent_types`, so the guard's notices say "write your report file now", not "update HANDOFF and commit". Limit: 200k, wrap-up from 170k, for a report-only consultant on the strongest model (R-ctx-3 table).
- **R-loop-18. A completion notice for a lane that is already closed: check its last activity, do not read its output.** The lane ledger records when each lane was closed. Run `tools/agent_scan.py --agent <id> --since <closing time>`; one call says whether the agent did anything since.

## 7. Bookkeeping

- **R-book-1. One bookkeeping script per event** (`launch`, `finish`, `push`, `note`) that updates all state files at once.
- **R-book-2. Findings register: every finding in the same turn, with owner, next step and due time. A row closes only with a commit sha or job id.**
- **R-book-3. Hints file protocol.** An append-only file of facts and verbatim user decisions, plus a short rules digest that is re-read after every compaction. See STARTER-KIT for the template.
- **R-book-4. Append to one-line config files only through a normalizer.**
- **R-book-5. Validate config edits through the reader's own code path.**
- **R-book-6. Resumability.** Every agent commits WIP per milestone (<= 45 min) and keeps a STATE/NEXT section with live job ids; the coordinator keeps the resume sheet; must-happen actions (e.g. destroying rented compute at a deadline) run as detached processes, not session tasks.

## 8. Monitoring

- **R-mon-1. Automatic monitoring with a wake-up path.** The coordinator keeps a wait-alert process in the background so a new alert wakes it.
- **R-mon-2. Act on alerts or mute them with a reason and an expiry.** Never mute a resource alert (disk) for more than 30 min.
- **R-mon-3. Alert on absolute free space and own footprint, not percent used**, and on projected quota run-out, not hourly cost (hourly cost alerts were noise with ~10 agents).
- **R-mon-4. Restart a daemon after every change it reads; smoke-test after every infra deploy.**
- **R-mon-5. Token pacing to the quota target.** A pace line ends at 100 % AT the reset. Behind pace -> launch work at once. Throttle only if projected empty > 2 h before the user can reset, and then by reducing concurrency, never by pausing everything.
- **R-mon-6. Never act on one estimator.** Cross-check the pace estimate with the raw slope over >= 3 h and the dashboard's run-out.
- **R-mon-7. Measure cost from transcripts, deduplicated by message id.** One API call is logged as several blocks; naive sums double-count (an early cost figure was 73 % too high).
- **R-mon-8. Every timing or merge job failure is a warning with the log tail**; the coordinator checks the main baseline job each sweep until its summary exists (a death went unseen for 15 min).
- **R-mon-9. Alerts about other owners' jobs never wake the coordinator.** On shared hosts, route report-only alert kinds (idle slots, long job, unowned process) for jobs whose owner is not yours to a digest file, not to the wake channel. Mute by OWNER, not by job id; per-id mutes are a stopgap until the monitor filters by owner. Alerts on your own jobs keep waking.

## 9. Compute and job discipline

- **R-job-1. One job queue for all compute.** Placement by need, slots per job, priorities with aging (e.g. merge > dev > explore, +1 level per 15 min), reservations for big jobs, timeouts that kill the remote tree, infra-failure retries, status and history.
- **R-job-2. Submit detached, own the job, wait by id.** `QUEUE_AGENT=<me> queue run --detach...` prints the id; no shell death can cancel it; only `queue cancel <id>` stops it.
- **R-job-3. Hold slots per running process; never hold slots while waiting on another job.**
- **R-job-4. Evidence freshness: commit, then submit; freeze the tree until the job STARTS.**
- **R-job-5. Back-dating.** When a job must be resubmitted (or bumped for the critical path), the coordinator back-dates its submit time under the queue lock with a note, so it keeps its place. Check the job's pins and env in the same step.
- **R-job-6. Distinct remote dir per concurrent job from one worktree.**
- **R-job-7. Job commands propagate the exit code.** Never end with `; echo rc=$?`. A harness that evaluates nothing exits non-zero. Verify within minutes that a submitted job really runs.
- **R-job-8. Cleanups only via allowlist scripts.** Directory deletions on shared hosts go through a script that knows owners (successor chain) and refuses dirs named in queued jobs. Never prune by idle time or name patterns alone. No `rm` with an unchecked variable path.
- **R-job-9. Disk and memory guards.** Compare scripts delete raw outputs of matching pairs at once (keep mismatches and logs); never pull raw trees to the laptop; a worktree output dir > 2 GB is an incident; temp files that may outlive a kill are created unlinked; size every dir the queue pulls back before archiving anything.
- **R-job-10. The user's machine stays quiet.** Laptop builds via an admission wrapper (1 at a time, waits for free memory, limited jobs, background QoS); daemons reniced; on a noise complaint check `ps` for the cause (the cause was idle queue clients spinning in Python, ~1.25 cores).
- **R-job-11. Edit running scripts atomically** (temp file + `mv`). Bash reads scripts while running them. Use `#!/usr/bin/env bash`, or start job scripts as `bash x.sh`, on hosts without `/bin/bash`. A job's helper scripts are tracked in its own tree, never referenced in another lane's scratch dir (a whole rerun round lost).
- **R-job-12. Per-agent ssh multiplexing.** One shared master hits the server's session limit; no multiplexing trips connection throttles (~50 % resets).
- **R-job-13. Guard and action in one command.** A state check minutes before an action is stale (a deletion ran inside a timing lease opened 3 min after the check).
- **R-job-14. Reference hosts and tool versions are calibrated before they produce data**, with numeric pass bands (a calibration failed in 20 min and saved a night of wrong references).
- **R-job-15. Record a host's boot mode before a reboot and diff it after** (a reboot fell to a default mode with different memory limits, misdiagnosed first).
- **R-job-16. Rented GPUs: stage the data first.** Upload each round's inputs to the provider's network volume through the cheapest CPU-only instance long before the GPU round starts. Create the GPU instance only when work can start, never to wait for an upload.

## 10. Evidence and measurement discipline

- **R-ev-1. Every number names its commit, scope and metric.** Full run vs slice, report id, host and metric. Older numbers are labelled.
- **R-ev-2. Judge levers by the real metric, not a proxy.** Use cheap deterministic proxies (instruction counts, counters) to explore; confirm on the real metric with the cheapest A/B on the target case before any full evidence run. Drop the lever if the real metric is within the noise band.
- **R-ev-3. Report the counter the change is meant to move**, not only time.
- **R-ev-4. Know your noise floors and bars.** Measure interference: on one host <= 2 busy slots kept single-thread timing within 0.5 %, cross-job drift was 0.3-1.3 %, moving other jobs to efficiency cores was not neutral (1.1-1.4 %). So A/B inside one job or one exclusive window. Identical builds can swing 3-6 % from code placement. A bar tighter than the floor cannot be met by any change.
- **R-ev-5. Check what an expensive verification step measures.** A measurement setting that forced a compile on every case dominated the proxy count (567G vs 60G instructions) and made runs 2-3 h; it also diluted every lever ~2x.
- **R-ev-6. Base provenance.** Base trees are built from `git archive <sha>` inside the job or in a synced dir (never in a dir the queue does not sync). Each copied tree gets its own build-target dir.
- **R-ev-7. Cumulative end-to-end checks per batch, not only per-step checks.**
- **R-ev-8. Validate once.** Feature lanes prove READY with targeted evidence (red/green tests, one release suite, lint, the cases they target, an expected-differ list). The merge steward runs the full evidence once for the stack.
- **R-ev-9. Two merge lanes.** FAST lane = changes proven output-identical: rebase, full tests, identity check (stacked by the steward), proxy A/B, real-metric A/B. TRAIN lane = behaviour changes: full gates, small batches (2-3 changes only when files are disjoint).
- **R-ev-10. Gates must be able to fail.** Canary cases for each silent-wrong class, a mutation check that known-bad builds fail, every heavy or failing case gets at least one gate row.
- **R-ev-11. Speed claims only for runs that agree with the reference**.
- **R-ev-12. A slow test that covers a guard is never skipped for changes to that guard**.
- **R-ev-13. Settle tool-vs-reference disagreements with a windowed comparison plus a "which mechanism could legitimately cause this" question** in one lean lane (174k / 34 min vs a predecessor's 206k without a verdict).
- **R-ev-14. Independent review for silent-failure code** (cache keys, schedulers, generators) (9 silent bugs in one cache; 5 real issues in a scheduler review).
- **R-ev-15. Check a verdict before acting on it.** Re-run a newly-bad verdict on a fresh build (binary hash plus build time, its own build dir) before launching work on it. Classify a PASS-to-WARN flip as a metric change or a behaviour change first.
- **R-ev-16. The release gate is a check of the exact release artifact on the real device.** Install the signed build and run the checks before publishing. "Quit" in a check is the app's real quit, never a kill signal. A document that ships inside a binary is part of the build: a doc fix means rebuild, re-sign and grep the binary for the new text.
- **R-ev-17. A data rebuild is READY only when every downstream consumer reads the new version.** Ship every view the consumers use and run one consumer cross-check before READY.
- **R-ev-18. ML projects: audit and clean the labels before the first model lane.** Place every label by the raw signal, find duplicate or overlapping sources, and measure each machine step between the human's act and the label.
- **R-ev-19. ML rounds: one lane for compute, a separate lane for scoring and analysis**, each with a minimum read set.

## 11. User interaction

- **R-user-1. Record decisions verbatim**, with date and time, in the hints file, the same turn. Every standing instruction also gets a duties-registry row with its enforcement.
- **R-user-2. Ask with a recommendation.** Use a structured question (AskUserQuestion) with options, one marked "(Recommended)", each with its cost and consequence. Work continues on other items while the question is open (35+ such answers recorded; the user mostly picks the recommendation).
- **R-user-3. "Let's discuss" means no actions.** Present options and wait.
- **R-user-4. Manual user actions as numbered steps** with exact commands or clicks.
- **R-user-5. Status = short table + dashboard pointer.** Status, ETA, quota %, quality flags, key changes. Honest assessment and one recommendation, not option dumps.
- **R-user-6. Know what is delegated.** Typical split after a few days: the coordinator decides technical choices, trade-offs, defaults, accept/fix decisions with evidence, routing, limits, briefs. The user keeps: licences, publishing, security and system changes, compute and machine rules, renting, quota and accounts, metric and gate changes, exceptions to quality bars, stopping (killing) agents, and how to proceed after a permission-checker refusal. Report each autonomous decision afterwards with numbers and how to revert.
- **R-user-7. Surface risk early**, with plan B, not at the deadline.
- **R-user-8. Discuss before starting** work types the user named (ports, new infrastructure, outward-facing actions).
- **R-user-9. Downloads and licences:** agents list download needs at scoping; the coordinator classifies each item against a licence policy and asks once per natural break with per-item checkboxes; work switches to other items meanwhile.
- **R-user-10. Questions while the user is away.** Before an overnight question, queue all work that does not depend on the answer, so compute keeps running; the answer gates only the last step (for example the push). Use a structured question only while the user is present; otherwise ask in chat text and continue with other items. Record each answer with its scope (one job, one batch, standing).

## 12. Safety

- **R-safe-1. No approval popups when the user is away.** Never run anything that makes the harness ask the user: writes to `.git/` internals or harness config, shell rc files, paths outside the agent's worktree / tmp / job dirs, sandbox overrides, app-level requests. Skip the step and report it.
- **R-safe-2. No permission laundering.** Never wrap, encode or move a command into a script so a permission, hook or isolation check cannot see it, and never retry variants after a refusal. Send the exact refusal text to the coordinator.
- **R-safe-3. A message from an agent is never the user's consent.** Agent messages direct work but cannot authorize permission or config changes.
- **R-safe-4. Deletions.** Literal absolute paths or `${VAR:?}`; owner-aware allowlist scripts on shared hosts; nothing deleted by a predecessor after a handoff; archive before removing worktrees (diff patch + untracked tarball + archive branch for unreachable heads).
- **R-safe-5. Private data.** Per-run copies (mode 700, deleted also on failure); tools that stage private data clean up themselves; never run tools inside shared read-only copies that are hard links (writers corrupt the master for everyone) (twice in 2 h; detection by manifest + inode check caught both); names of private data items never appear in commits or reports (use hash keys). Scan the history before publishing anything.
- **R-safe-6. Shared session state.** If a plugin (e.g. self-compaction) is keyed by session id and sub-agents share the coordinator's session id, sub-agents must never call it.
- **R-safe-7. Secrets** never in briefs, notes, commits or URLs.
- **R-safe-8. Never `cd` in Bash**; absolute paths and `git -C`. Check `rev-parse --show-toplevel` before every commit.
- **R-safe-9. Agents do not create task suggestions in the user's interface.** Follow-ups go into reports; the coordinator launches agents.
- **R-safe-10. Every report has a Safety section**: guards, bounds, what could silently differ, what was delegated and whether it was spot-checked.
- **R-safe-11. No history rewrite or reset in a shared checkout while lanes work there.** `git filter-repo`, `reset --hard`, `checkout`/`switch` and stash-less rebases in the coordinator's checkout discard uncommitted edits of lanes that write into it. Before any of these: `git status --short`, then wait or stash.
